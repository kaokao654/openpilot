# Mr One C3 / 未开通 AP 的 Model S AP1：RDF 迁移预检

状态：方案与只读工具。没有修改模型进程、车辆控制、Panda 固件或安装流程。

## 已确认的条件

- Mr One 复刻 comma 3，可 SSH。
- Model S AP1，未开通 AP 软件，只有 AP1 线束，无 Pedal。
- 当前分支 `tesla_unity_releaseC3`，提交 `c0901fc97b02553315f6e9e88e6c8eb797ca850f`。
- 当前转向可用，纵向通过原车巡航调速；约 30 km/h 以下人工控制。
- 第一款目标模型 RDF V4；验证完整后，再在同一接口上比较 TSFDO。

## 最可能的主路线

**以已支持目标模型的平台固定提交为底座，迁入 Tinkla 的未开通 AP 状态管理与 ACC 巡航调速适配。**

候选运行底座为 StarPilot `823a5d5674ec6635b51dd989884dfbd661f90dc4`，现有 HW1 车辆代码、C3 相机支持及 v15 统一模型运行器均已存在。这是源码研究候选，尚未证明该系统可在本台 Mr One 设备上运行。

Mr One 官方安装页列出了 StarPilot：<https://mr-one.cn/?post=69>。但本次未能读取其极狐 GitLab 分支源文件，不能据此断定该版本支持本机、包含 RDF V4/TSFDO，或与上述提交相同。先核对厂商的相机、驱动、系统与 Panda 差异，再选择能复现的公开底座；不能直接把厂商安装地址当成本车可用版本。

两款模型的源版本固定为：

| 模型 | 上游源码提交 | StarPilot 模型 ID/行为版本 |
|---|---|---|
| RDF V4 | `a5a6412d08474cffb49a69afb910756afdee123e` | `rdf43` / v15 |
| TSFDO | `0394d7284cfc229f772ee4fa73ff724ba8245110` | `tsfdo` / v15 |

模型源版本、编译工具版本、模型文件校验值、运行底座与 Panda 固件必须分别固定。上线安装包应带清单，不能跟随远端目录自动更换权重。

## 为什么先不把新模型直接放进旧 Tinkla

旧库 `cereal/log.capnp` 的 `ModelDataV2` 没有新模型使用的 Action 结构；旧控制器通过 lateralPlan、longitudinalPlan 工作。新模型运行器还依赖不同的 visionipc、相机输入处理、tinygrad、解析和规划接口。直接回移涉及整条模型链，而非替换 `supercombo.thneed`。

BogPilot 与 StarPilot 旧 0.9.7 线也没有原样具备当前统一 v15 模型接口。若选它们，同时要做新模型运行器移植及未开通 AP 车辆适配。对已经固定 RDF/TSFDO 的目标，目前主路线预计更可控；这不是已完成的工期估算或实车可靠性结论。

若本机无法稳定运行候选底座，则暂停该底座的控车适配，研究厂商支持系统中的独立模型试运行；根据实际缺失接口，再判断回移是否值得做。

## 要迁移的车辆行为

1. Tinkla 的软件巡航启用状态、拉杆操作、人工接管和退出规则。
2. 原车巡航加减速的 0x45 报文、计数器、校验、频率及速度目标转换。
3. 当前 Tinkla 通过 HUD 消息 0x659 传递特殊模式的机制。它是控制许可协议的一部分，需要明确替代或保留，不能当作纯显示消息删除。
4. HW1 专用安全状态与消息约束。新平台现有 HW1 TX 列表没有旧 ACC 调速所需的 0x45；须在准确车型/模式中增加可测试的有限规则。不能整体取消检查或扩大为任意发送。
5. 当前已知的纵向速度范围和人工接管提示。本阶段不扩展低速控制能力，不启用另一套 DAS_control、Pedal 或 iBooster 执行路线。

现代 Tesla、Pre-AP 与本车的未开通 AP1 模式必须可区分，不能复用一个含义不明的标志。

## 当前只读工具的使用

本工具仅使用 Python 标准库，正常 Python 3 环境即可。它读取明确列出的系统文件、一个 Tinkla 参数、USB 产品 ID、代码版本；可选计算当前模型的 SHA-256。不会打开 Panda、发送 CAN、访问网络、更换软件、更新固件或控制进程。

不导出 VIN、设备序列号、IP、Git 远端、SSH 密钥、登录令牌，也不导出全部参数。它无法确定 Panda 的实际固件/安全状态、摄像头帧格式、推理性能或完整硬件兼容性；这些需要后续专门核对。

无需在设备上切换本分支。在电脑下载本文件，再复制到设备临时目录：

```sh
# 在电脑执行，替换 COMMA_IP 为设备局域网 IP
scp device_inventory.py comma@COMMA_IP:/tmp/ap1_device_inventory.py
ssh comma@COMMA_IP 'python3 /tmp/ap1_device_inventory.py --repo /data/openpilot --hash-models' > ap1_device_inventory.json
```

如果电脑下载后的文件在其他目录，请相应调整 scp 的源路径。仅上传 Python 文件；`/data/openpilot` 指定当前安装位置。不要在设备执行 checkout、pull、安装脚本或更新 Panda。

JSON 的缺失字段表示未读取到，不应当作“不支持”的结论。后续备份会分开保存在设备本地，包含的参数与日志不会批量推送到公共仓库。当前工具没有实现备份或日志导出。
